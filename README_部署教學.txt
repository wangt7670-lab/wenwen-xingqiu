《問問星球》V4｜資料出題、房間題庫及雙人闖關
========================================================

正式站 https://rainbow-licorice-078d2c.netlify.app/
前端與 Netlify Functions 共用同一 Git 專案。正式站部署前先在獨立環境驗收。

一、使用方式

- 原有雙人邀請、手動出題、內建題庫、計分及戰績沿用原本的房間。
- 「快速出題」可依主題、關鍵字、難度和風格從 150 道內建題整理 1／5／10 道草稿。
  沒有符合條件的題目時可調整篩選。近期文章可由使用者提供作為資料來源。
- 「資料出題」支援貼文字及 UTF-8 TXT、Markdown、可選取文字的 PDF 和 DOCX。
  每份最多 3 MiB，PDF 最多 40 頁。擷取前 120 段可用文字，附段落或 PDF 頁碼。
  解析只擷取文字。掃描圖像需先取得文字。
- 規則式出題從定義、日期、數量與原文段落建立草稿。四選一只採用資料內可區分的候選；
  當可核對的題目少於要求題數時，介面會顯示實際數量。可改用簡答出題。
- 文件草稿在此頁面編輯，重新整理前請完成需要的審核與分享。分享至房間題庫會同步題目
  與引用片段；其他玩家作答前看不到正解。原檔的列出、下載和刪除均限上傳者。
- 闖關從房間題庫選 3 至 5 道題，兩位玩家輪流答。簡答按參與給星，四選一按正確性給星。
  闖關星星獨立顯示，舊有戰績照常保存。重新載入後可從同一關繼續。
- 刪除原檔將刪除連結的題庫題目。已寄出的問答和已開始的闖關保留當時共享的內容。
  房間到期一天後，排程清理移除原檔和文件索引。過期房間本身的清理沿用原本的管理方式。

二、隔離環境與部署

1. 本機使用 Node.js 22.13 或以上，執行 npm ci、npm test 和 npm run build。
   npm run dev 會先打包前端資產，再啟動 Netlify Dev。
2. 獨立 Supabase 環境先執行 supabase/schema.sql，再套用
   supabase/migrations/20261120020000_v4_library.sql。遷移只新增題庫、文件、闖關和私有 bucket。
3. 在 Netlify 設定 Functions 的 SUPABASE_URL 及 SUPABASE_SECRET_KEY。預覽與正式環境
   使用不同的 Supabase 專案。設定預覽變數後分別核對專案識別碼，再開放測試連線。
   OpenAI API 金鑰已無需配置。除非自行驗收本地模型，ENABLE_LOCAL_AI 保持 false。
4. 先在預覽做兩位玩家的跨房、跨玩家、刪除及續玩測試。檢查正式站歷史機密掃描警報
   及金鑰作用範圍；確認正式庫備份和專案識別碼後，再套用正式庫遷移及發布 Git 版本。
5. 發布後用部署前建立的合成測試房間驗證原有戰績、答案保密及計分。若要回滾，應
   從 Netlify 恢復先前發布版本並保留新增資料表，使預覽中的新資料仍可復原。由於清理
   排程也會隨已發布版本回滾，長期回滾時需監看私有文件保留與清理。

三、私有資料與用量

- 房間邀請碼用於加入。伺服器另查驗玩家憑證、房間及上傳者 ID 才可存取原檔。
- Supabase 新表啟用 RLS。私有 bucket 有額外限制政策，匿名和登入角色均由後端代理
  存取這個 bucket，服務金鑰只用在 Functions。正式資料和檔案不得匯入預覽庫。
- 每房最多 6 份文件、100 道題。所有原檔的應用層容量上限為 250 MiB。
  到期或上傳中斷留下的檔案由排程處理。請在 Netlify 的 Functions 清單驗證排程已生效。
- 請勿把金鑰放在 Git、靜態前端、部署日誌或支援對話中。Netlify 的機密掃描應保持開啟。
- 可選本地 AI 需要支援 WebGPU 的安全來源。使用者按「在此裝置改寫題幹」後，
  瀏覽器下載公開模型檔至本機，之後本機只處理所選題幹與引用片段。模型不改動
  答案和來源，改寫後仍需審核。模型不支援或下載失敗時，可直接編輯既有草稿。
- Chrome 內建 Prompt API 當前未列繁體中文，因此本功能採 WebLLM 的中文模型，首次下載
  可能需要數百 MB。請先在支援裝置驗證繁中改寫與效能，再設定 ENABLE_LOCAL_AI=true。
